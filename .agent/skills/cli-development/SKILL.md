# Noxs skill: cli-development

purpose: Modify the guest CLI templates and their generated launcher copies.
when_to_use: Any change to noxs-cli or nx behavior, help text, docs deep links.
required_context: NoxsCliTemplate.kt is the canonical noxs script; linux-runtime/launcher/noxs-cli is GENERATED by scripts/sync-cli.sh. Every $ in the Kotlin raw string is written ${'$'}.
relevant_files:
  - app/src/main/java/com/crossberry/noxs/runtime/NoxsCliTemplate.kt
  - app/src/main/java/com/crossberry/noxs/runtime/NoxsNxTemplate.kt
  - linux-runtime/launcher/noxs-cli (generated)
  - app/src/main/resources/documentation/commands.json
workflow:
  1. Edit the Kotlin template (never the launcher copy).
  2. bash scripts/sync-cli.sh
  3. bash -n linux-runtime/launcher/noxs-cli && shellcheck it.
  4. bash scripts/test-code-cli.sh for the code-server regression suite.
  5. Update commands.json + NoxsDocsMap if help/docs changed.
coding_rules: Help text documents ONLY existing commands; unknown inputs print valid alternatives + docs URL; truthful exit codes.
security: No secrets in help examples; bridge ops validate ids ([A-Za-z0-9._-]).
testing: DocumentationMetadataTest (dispatch <-> commands.json <-> docs map alignment).
documentation_updates: reference/cli-reference/ + commands.json (doc_sync.py affected).
checklist:
  - sync-cli.sh run
  - shellcheck clean
  - metadata + tests updated
